# Outdoor ARCore Geospatial prototype

This prototype is isolated from `IndoorAr` and the existing AR session setup. The ARCore Extensions package is included, but Geospatial mode remains disabled until a separately approved Google Cloud project and authorization are configured. No cloud project, key, billing, VPS query, or campus coverage check was created or performed for this change.

`OutdoorGeospatialReadiness` reads ARCore's device support, Earth service state, tracking state, and pose accuracy. Its host must supply the user's consent and camera/location permission results, and explicitly call `CheckVpsAtCurrentPosition()` after setup. The VPS result expires when the tracked position moves more than 5 m from the queried point. `OutdoorGeospatialGate` is the only route to an outdoor guidance anchor. The feature must be enabled and the user must acknowledge Google's device-data use; the device must support Geospatial; camera and precise location permissions must be granted; the Geospatial service and point-level VPS check must succeed; and Earth tracking must be active with horizontal accuracy at most 5 m and heading accuracy at most 10°. All other states deny anchor placement. The thresholds are conservative prototype choices and need real-device validation.

Before device validation, create a dedicated outdoor AR scene/session, configure the ARCore Extensions settings and Geospatial session mode after Google Cloud authorization, provide camera/location permission results, and use the readiness component's state for the UI. Do not reuse MultiSet poses or claim campus coverage. Current code does not configure a Google service, start a camera session, request permissions, or create anchors; it does not change indoor scenes/build settings. A VPS request runs only when the component is explicitly asked and all preceding gates pass.

The Unity project uses 6000.3.26f1, AR Foundation/ARCore XR Plugin 6.3.5, and ARCore Extensions 1.57.0 AR Foundation 6 tag. Google's 1.53.0 release notes report the Unity 6.3 compile fix; device and package-resolution validation is still required.
